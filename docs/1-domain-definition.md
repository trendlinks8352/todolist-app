## 1. 프로젝트 개요

### 목적

개인 사용자가 자신의 할일을 체계적으로 등록, 관리, 추적할 수 있는 인증 기반 할일 관리 애플리케이션을 제공한다. 사용자 계정 단위로 데이터를 격리하여 개인화된 할일 관리 환경을 보장하며, 카테고리 및 다양한 필터링을 통해 효율적인 업무 관리를 지원한다.

### 범위

| 구분 | 포함 |
|------|------|
| 사용자 인증 | 회원가입, 로그인, 로그아웃, 회원 탈퇴 |
| 사용자 관리 | 개인정보 조회 및 수정 |
| 할일 관리 | 등록, 수정, 삭제, 완료 처리 |
| 카테고리 관리 | 기본 카테고리 제공, 사용자 정의 카테고리 생성·수정·삭제 |
| 필터링 조회 | 카테고리별 / 기간별 / 완료 여부별 |
| 외부 연동 | 범위 외 (알림, SNS 연동 등 제외) |

## 2. 핵심 도메인 개념 (Ubiquitous Language)

| 용어 | 정의 |
|------|------|
| 사용자 (User) | 회원가입 후 인증을 통해 서비스를 이용하는 주체 |
| 인증 (Authentication) | 사용자의 신원을 확인하는 로그인 절차 |
| 할일 (Todo) | 사용자가 수행해야 할 단위 작업. 제목, 설명, 종료예정일, 카테고리를 포함 |
| 카테고리 (Category) | 할일을 분류하는 그룹 단위. 기본 카테고리와 사용자 정의 카테고리로 구분 |
| 기본 카테고리 (Default Category) | 시스템이 모든 사용자에게 공통 제공하는 불변 카테고리 (예: 일반, 업무, 개인) |
| 사용자 정의 카테고리 (Custom Category) | 인증된 사용자가 직접 생성한 카테고리 |
| 완료 여부 (Completion Status) | 할일의 처리 상태. 미완료(Pending) 또는 완료(Completed)로 구분 |
| 종료예정일 (Due Date) | 할일을 완료해야 하는 목표 날짜 (당일 포함, 오늘 이후만 허용) |
| 할일 소유자 (Todo Owner) | 해당 할일을 등록한 사용자. 본인만 접근 가능 |

## 3. 도메인 엔티티 및 속성

### User (사용자)

| 속성 | 타입 | 설명 | 제약 |
|------|------|------|------|
| id | UUID | 사용자 고유 식별자 | PK, Not Null |
| email | String | 이메일 주소 (로그인 ID) | Unique, Not Null |
| password | String | 암호화된 비밀번호 | Not Null |
| name | String | 사용자 이름 | Not Null |
| createdAt | DateTime | 계정 생성일시 | Not Null |
| updatedAt | DateTime | 정보 수정일시 | Not Null |

### Todo (할일)

| 속성 | 타입 | 설명 | 제약 |
|------|------|------|------|
| id | UUID | 할일 고유 식별자 | PK, Not Null |
| userId | UUID | 소유 사용자 ID | FK → User, Not Null |
| categoryId | UUID | 분류 카테고리 ID | FK → Category, Not Null |
| title | String | 할일 제목 | Not Null, 최대 200자 |
| description | String | 할일 설명 | Nullable |
| dueDate | Date | 종료예정일 | Nullable |
| isCompleted | Boolean | 완료 여부 | Default: false |
| completedAt | DateTime | 완료 처리 일시 | Nullable |
| createdAt | DateTime | 등록일시 | Not Null |
| updatedAt | DateTime | 수정일시 | Not Null |

### Category (카테고리)

| 속성 | 타입 | 설명 | 제약 |
|------|------|------|------|
| id | UUID | 카테고리 고유 식별자 | PK, Not Null |
| userId | UUID | 소유 사용자 ID (기본 카테고리는 Null) | FK → User, Nullable |
| name | String | 카테고리 이름 | Not Null, 최대 50자 |
| isDefault | Boolean | 기본 카테고리 여부 | Default: false |
| createdAt | DateTime | 생성일시 | Not Null |

## 4. 핵심 비즈니스 규칙

**인증 규칙**
- BR-01. 미인증 사용자는 할일 및 카테고리 관련 모든 기능에 접근할 수 없다.
- BR-02. 이메일은 전체 시스템에서 유일해야 하며 회원가입 시 중복을 허용하지 않는다.

**데이터 격리 규칙**
- BR-03. 사용자는 자신이 등록한 할일만 조회, 수정, 삭제할 수 있다.
- BR-04. 사용자 정의 카테고리는 생성한 사용자만 사용할 수 있다.

**할일 규칙**
- BR-05. 할일 등록 시 반드시 하나의 카테고리를 지정해야 한다.
- BR-06. 완료 처리된 할일은 completedAt이 자동 기록되며, 완료 취소 시 completedAt은 초기화된다.
- BR-07. 종료예정일은 오늘 날짜 이후(당일 포함)로만 등록 및 수정할 수 있다.

**카테고리 규칙**
- BR-08. 기본 카테고리(isDefault=true)는 수정 및 삭제할 수 없다.
- BR-09. 사용자 정의 카테고리 삭제 시, 해당 카테고리에 속한 할일은 시스템 불변 카테고리인 '일반'(isDefault=true, name='일반')으로 자동 이관된다.
- BR-10. 동일 사용자 내에서 카테고리 이름은 중복될 수 없다. 비교 시 앞뒤 공백을 제거하고 대소문자를 구분하지 않는다.

## 6. 도메인 제약 조건

**데이터 무결성**
- DC-01. 사용자 계정 삭제 시, 해당 사용자의 모든 할일 및 사용자 정의 카테고리는 연쇄 삭제된다.
- DC-02. Todo의 categoryId는 항상 유효한 카테고리를 참조해야 한다. (Null 불허)

**입력값 제약**
- DC-03. 할일 제목은 1자 이상 200자 이하로 제한한다.
- DC-04. 카테고리 이름은 1자 이상 50자 이하로 제한한다. 앞뒤 공백은 저장 전 제거한다.
- DC-05. 비밀번호는 최소 8자 이상이며 영문, 숫자를 각각 1자 이상 포함해야 한다. 특수문자는 허용하나 필수 아님.

**접근 제어**
- DC-06. 모든 API 요청에는 유효한 인증 토큰이 포함되어야 한다. (공개 엔드포인트 제외: 회원가입, 로그인)
- DC-07. 타 사용자의 리소스에 접근 시도 시 403 Forbidden으로 응답한다.

**필터링 제약**
- DC-08. 기간 필터 적용 시 시작일은 종료일과 같거나 이전이어야 한다. 필터는 할일의 종료예정일(dueDate)을 기준으로 적용한다.
- DC-09. 필터 조건이 없는 경우 전체 할일 목록을 최신 등록순으로 반환한다.

## 7. 공통 에러 응답 정책

규칙 위반 시 아래 HTTP 상태 코드 기준을 일관되게 적용한다.

| 상황 | HTTP 상태 코드 | 설명 |
|------|--------------|------|
| 인증 토큰 없음 또는 만료 | 401 Unauthorized | 재로그인 필요 |
| 타 사용자 리소스 접근 | 403 Forbidden | 접근 권한 없음 |
| 존재하지 않는 리소스 | 404 Not Found | 해당 리소스 없음 |
| 입력값 제약 위반 (DC-03~05, BR-07, BR-10 등) | 422 Unprocessable Entity | 유효성 검사 실패, 위반 필드 명시 |
| 중복 이메일·카테고리명 (BR-02, BR-10) | 409 Conflict | 중복 데이터 충돌 |
| 기본 카테고리 수정·삭제 시도 (BR-08) | 403 Forbidden | 변경 불가 리소스 |
